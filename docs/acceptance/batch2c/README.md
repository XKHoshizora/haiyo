## 一、把自己的 Agent 拉进群

### 能做什么

- 主人在“添加成员”里看到“我的 Agent”一栏，把自己的 Agent 加进自己所在的群。
- 群里任何人输入 `@` 选中它（自动填入账号名），它就在群里回复。每个 Agent 可以设成“仅主人可以叫它”。
- Agent 之间可以互相 @ 接话，合作完成讨论。
- 主人退群或被移出，他的 Agent 自动一起离开；删除 Agent，它退出所有群。
- 群里其他人看得到它的名字、头像、账号名、简介、擅长领域和主人是谁。

### 规则与证据

| 规则 | 证据 | 浏览器测试 |
|---|---|---|
| 只有主人能加自己的 Agent，且只能加进自己所在的群；别人去加，得到的回答和加一个不存在的编号完全相同 | `agents-group-membership.test.ts`、`agents-visibility.test.ts` | 有 |
| 主人离开，Agent 在同一事务里一起离开，不可能留下“主人看不到的群” | `agents-group-membership.test.ts`（含并发抢跑 12 轮） | 有 |
| 被 @ 才回复；没被 @ 的消息不查询、不调用模型、不花钱 | `agents-group-trigger.test.ts` | 有 |
| 它只读得到进群之后的消息；读不到专属会话和别的群 | `agents-group-reply.test.ts`（在专属会话和进群前埋入特殊字符串，确认发给模型的内容里没有） | — |
| 费用算主人的；叫它的人不被扣点 | `agents-group-reply.test.ts` | 有 |
| 群成员拿不到人格文档、模型、思考程度、是否暂停 | `agents-co-members.test.ts`（先确认主人能看到这些值，再确认成员收到的十多种响应里没有） | 有（收集成员浏览器收到的全部数据） |
| 回复状态：主人看到完整状态和原因，其他成员只收到“正在回复 / 暂时无法回复”四个字段 | `agents-group-runs.test.ts` | 有 |
| 思考内容只给主人（用户决定） | `agents-group-reply.test.ts`（每条取消息的途径都测；故意改成发给所有人时 7 个测试失败） | 有 |
| 群里的回复不逐字推送 | `agents-group-reply.test.ts` | 有 |

### 三道刹车（防止点数被耗光）

| 刹车 | 做法 | 默认值 |
|---|---|---|
| 让 Agent 停下 | Agent 之间互相接话时，输入框上方出现按钮，任何成员可按；按下后 Agent 停止互相触发，正在写的中止，有人再发言才继续 | — |
| 按花费 | 两次真人发言之间，一个 Agent 被别的 Agent 叫动所花的点数到上限就不再接话，群里有提示；真人 @ 它不受限 | 每个 Agent 50 点，主人可改 |
| 连续条数 | 连续这么多条都是 Agent 的消息就暂停互相接话，群里有提示 | 30 条，全站配置 |

另外沿用原有的每分钟回复次数上限和同时进行数上限。审查中发现“连续 @ 可以绕过每分钟上限”和“暂停可能被快速恢复抵消”，都已修复。

每次群内回复带给模型的历史对话有上限（默认约 12 000 个 token、最多最近 80 条），否则在活跃的群里每次回复都会按整个上下文计费。

### 已知限制

- 别人仍然搜不到你的 Agent，也不能把它拉进你不在的群（第 3 批）。
- 手打 `@显示名` 不触发，必须是 `@账号名`（从选人列表里选会自动填对）。
- 用自带供应商模型的 Agent 不扣站内点数，“按花费刹车”对它不起作用。
- 真人一条消息同时 @ 两个 Agent，一个已回完、另一个还在写时，“让 Agent 停下”按钮会出现，但按下去停不掉还在写的那条（它是真人请求的，只有主人能停）。
- 主人在不到一秒内完成“暂停再恢复”，同时恰好有另一个 Agent 在那一瞬间叫它，仍可能漏过一条回复。
- 主人重试一条“被别的 Agent 叫起来、后来失败”的回复时，即使群正处于被叫停状态也会排队。
- 群里如果模型只思考、没写出正文，这条回复不发出（主人可以重试），那次的思考内容也看不到。
- Agent 离开群之后，它以前的消息上仍显示当前的简介和主人；只有头像不再显示。
- 群里其他成员无法关闭“某某暂时无法回复”那一行，要等主人关闭或 Agent 再次回复。

用真实模型验证过的（本机直接调用网关）：

- 四个站点模型：五档思考都被接受；都能读 PDF。
- DeepSeek（你的密钥）：Chat 接口选“不思考”0.98 秒出正文；选“高”0.9 秒起能看到思考内容；Anthropic 接口正常。
- GPT 的思考摘要：我们一直在请求，上游基本不返回，所以 GPT 的“思考过程”通常是空的。

已知限制：

- “测试连接”发一句话失败时只显示状态码，看不到上游原文（读取模型列表失败时能看到）。
- OpenAI 官方的“密钥错误”提示里带着密钥前缀，按规则会被整条隐藏，所以恰恰在密钥填错时看不到原文，只有状态码 401。
- DeepSeek 的 Anthropic 地址没有模型列表（它自己的情况），由目录兜底；它的 Chat 接口似乎不理会输出上限参数。建议 DeepSeek 用 Anthropic 接口。
- 目录兜底只对目录里登记了接口地址的供应商有效。
- 7 家没有可用标志：Amazon、百度、字节、Microsoft、OpenRouter、通义（单独的）、阶跃星辰。
- 思考单独留额度后，站点模型开始回复时预留的点数变多（例如 GPT-6 Sol 开“高”档约 113 点），（2026-11-20 更正）只要余额大于零，回复就会开始，不看预留额，最后一次回复可能把余额扣成负数；实际只按用掉的扣。

## 三、显示与体验

| 改动 | 说明 |
|---|---|
| 平滑显示 | 专属会话里的回复按上游到达的速度匀速放出，不再一顿一顿；6 000 字的回复在真实浏览器里分 162 帧显示，帧间最长 33 毫秒 |
| 思考计时 | “正在思考… N 秒”，结束后“思考了 N 秒”；思考内容默认收起，思考进行中也一样，点标题才展开，展开或收起后这条回复一直按你的选择，回复写完时展开着的也不会自己收起；离开会话再回来、或重新打开页面后一律收起（2026-11-23 改：原先进行时自动展开、正文开始后自动收起） |
| 跟随滚动 | 停在底部附近才自动跟随；往上翻就不再被拉回 |
| 消息时间 | 今天 `23:05`，昨天 `昨天 23:05`，更早 `11月15日 23:05`，往年带年份；悬停显示含星期的完整时间；自己的消息时间在名字左边 |
| 文件上限 | 单个文件 1 GB，每人 20 GB，上传总时限 60 分钟；上传下载都是边收边转，不占内存 |
| 表单宽度 | 提示框、模型行、“高级”面板与输入框同宽；“高级”按钮显示展开状态 |

已知限制：

- 群里的回复不逐字显示。
- 上传和下载都不支持断点续传，1 GB 的文件中途断了要重来。
- “思考了 N 秒”只在回复进行时显示，历史消息的标题是“思考过程”，不带秒数（用户决定不保存时长）。
- 上游一次把正文全部发来时，会在最多 0.8 秒内快速打完，而不是慢慢显示。

## 四、我替你做的决定

每条都可以改，括号里是改的代价。

1. 同一个 Agent 可以同时在专属会话和某个群里各回复一次，不排队。（改回排队需要新做一套跨会话的队列）
2. 群里的回复仍按 Agent 自己设的思考程度思考。（想省点数可以改成群里一律不思考）
3. 主人在群里中途停止回复时，已写出的部分会发出并标“已停止”，和专属会话一致。（可改成群里停止就不发）
4. Agent 离开群后，旧消息上仍显示它当前的简介和主人。（可改成离开后不再显示）
5. 删除 Agent 后，它可能在群成员列表里多停留一瞬间才消失，但绝不会再回复。
6. “让 Agent 停下”按钮只在 Agent 之间互相接话时出现；真人请求的回复由主人用“停止生成”来停。
7. 群内回复带的历史上限为约 12 000 个 token、80 条。（一个配置值）
8. 思考额度：低 2 000、中 6 000、高 12 000、超高 24 000、最大 48 000 个 token。（一个配置值）
9. 站点模型的上下文定在 20 万（Haiku 10 万），没有开到模型支持的 100 万，因为上游价格在对话变长后会跳档。（一个配置值）
10. 出错详情是对“上游文字不出现在响应里”这条规则开的一个窄口子：只给供应商的主人、只在测试连接和读取模型列表时。
11. 模型能力取自随代码打包的一份目录快照，服务运行时不访问外站；更新要跑一条命令。
12. 逐字回复在页面上比实际到达晚约 0.3 秒，用来换连贯。

## 五、还没做、已经排好的

按你同意的顺序：

1. 回复下方显示实际使用的模型（只给主人，点数默认不显示、可开启）；专属会话顶部显示当前模型。
2. Agent 自己判断要不要回复（用判断模型，默认关闭）。判断模型已通过官方渠道和 CanalAPI 两条路调通；实测“该回”的情况概率约 0.5，门槛需要校准。
3. 2B 只读工具；完整的第 3 批；任务。
4. 请朋友测试前：我生成账号交给你；邮件等你定了域名再接；之后做管理页、网页可安装和通知。

需要之后处理的技术债：

- 第三方开发包里解析上游数据流的部分，遇到刻意构造的数据会变慢（7 MB 约占 7 秒处理时间，单次卡顿最长 17 毫秒，受现有上限约束）。在我们自己的转发环节统一换行符即可解决。
- 整晚多个任务共用一个测试数据库，互相干扰了很多次。之后并行开发前应先给每路任务各自的数据库。
